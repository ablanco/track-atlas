# Login Modal and Logout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add localized top-bar login through an accessible modal and current-session logout, both preserving the current page.

**Architecture:** Extend the existing server-only authentication modules for password verification, session rotation, revocation, and purpose-bound ALTCHA. Add testable action orchestration and thin Next.js adapters, with request-time header state under Suspense and a client modal. Cookie mutations re-render the current route in the action response without a redirect or follow-up navigation.

**Tech Stack:** Next.js 16.4, React 19.3, TypeScript, next-intl, Drizzle/pg, existing PostgreSQL, native dialog, Phosphor, ALTCHA, Node test runner/tsx, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-15-login-design.md` (approved).

## Global Constraints

- Work directly on `master`; no feature branch or worktree.
- Reuse existing packages; no new auth/UI library, schema migration, or environment variable.
- Modal: email, password, ALTCHA, localized signup link; regular `XIcon` from `@phosphor-icons/react/dist/csr/X` with an accessible label.
- Login/logout preserve pathname, query, hash, and scroll; no return URL or login-success redirect.
- Authenticated signup renders an already-signed-in notice/home link, not a guest form or redirect; signup success still redirects home.
- Keep English/Spanish copy in message catalogs and semantic site theme tokens.
- Login passwords are untrimmed, nonempty, at most 1,024 UTF-8 bytes; email is trimmed, format-checked, at most 254 characters.
- Strict current scrypt encoding only: `v=1`, `N=32768,r=8,p=3`, 16-byte salt, 64-byte key. Share the existing two-concurrent-operation resource guard with signup.
- Keep 30-day database-backed sessions and cookie policy; logout revokes only the current session.
- Verify and atomically consume purpose-bound ALTCHA before password work; no verification bypasses in tests.
- Do not commit or push implementation unless requested. Use task checkpoints in this file instead of automatic per-task commits.

## Review Focus

- A stale/expired cookie must not prevent login or make logout fail: unit/DB/browser cases in Tasks 3–5.
- Password/hash corruption must not create unbounded work or reveal account existence: strict encoding and dummy-work tests in Tasks 1/3.
- Signup and modal may coexist: unique input IDs, scoped CAPTCHA helpers, and signup-page login/logout tests in Tasks 4/5.
- Delayed actions must not close/reuse the wrong modal or lose URL/scroll state: pending dismissal and preservation tests in Tasks 4/5.
- Cookie-triggered route rendering must refresh the header/home CTA without reintroducing theme-script or blocking-route errors: shared fixture plus production tests in Task 5.

## Task 1: Safe password verification and shared capacity

**Interfaces:** Extend `auth/password.ts` with
`verifyPassword(password: string, encoded: string | null): Promise<boolean>`.
`null` or unsupported encodings run fixed-parameter dummy scrypt and return false.
Keep `hashPassword` and `HashBusyError` exports unchanged; both functions share
one two-operation limiter. A valid encoding uses canonical base64url segments.

- [ ] Add tests in `tests/auth/password.test.ts`: correct password returns true;
      wrong/trimmed password returns false; spaces survive; malformed version,
      arbitrary work parameters, bad canonical encoding, wrong salt/key lengths,

      mock where needed to assert dummy verification uses exactly the fixed cost
      without brittle wall-clock comparisons.
- [ ] Add mixed-operation test: start hash and verify concurrently, third hash
      or verification rejects `HashBusyError`; completing/failing work releases

## Task 3: Login/logout services and testable actions

**Interfaces:**

- `LoginInput = { email: string; password: string }`;
  `LoginField = "email" | "password"`;
  `validateLogin(form: FormData)` returns discriminated success/input or
  errors plus `{ email: string }`, using signup's `ValidationCode` values.
- `LoginResult = { ok: true; session: IssuedSession } | { ok: false; reason: "invalidCredentials" | "unavailable" }`;
  `loginUser(db: AuthDatabase, input: LoginInput, previousToken?: string): Promise<LoginResult>`.
- `revokeSession(executor: Pick<Database, "delete">, token: string | undefined): Promise<void>`;
  missing/malformed tokens avoid DB access; otherwise delete only matching digest.
  Extend `AuthDatabase` with `delete` while retaining existing members; transaction
  executors already provide select/insert/delete.
- `LoginActionState = { values: { email: string }; fieldErrors: Partial<Record<LoginField, ValidationCode>>; formError?: "captcha" | "invalidCredentials" | "unavailable"; success?: boolean }`;
  `handleLogin(locale: string, form: FormData, dependencies: LoginDependencies): Promise<LoginActionState>`.
  Dependencies: `verifyCaptcha(form): Promise<boolean>`,
  `authenticate(input): Promise<LoginResult>`, `setSession(session): Promise<void>`.
- `LogoutActionState = { success?: boolean; formError?: "unavailable" }`;
  `handleLogout(dependencies: LogoutDependencies): Promise<LogoutActionState>`.
  Dependencies: `revokeCurrent(): Promise<void>`, `clearSession(): Promise<void>`.

- [ ] Add validation unit cases for missing, duplicate, file, malformed email,
      excessive UTF-8 password, safe bounded email echo, whitespace preservation,
      and ignored privilege fields. Add action tests asserting ordered
      `captcha → authenticate → cookie`, no credential work after invalid proof,
      generic infrastructure errors, no token/password reflection, invalid locale
      rejection, and no redirects. Logout tests pin `revoke → clear`, idempotency,
      no cookie clearing on DB failure, and cookie-effect failure reporting.
- [ ] Add live DB tests using unique fixtures/scoped cleanup or rollback:
      case-insensitive correct credentials issue one session; incorrect/unknown/
      inactive/malformed-hash accounts issue none with the same reason;
      unconfirmed accounts can log in; stale/malformed prior token does not block;
      successful rotation removes only the supplied old session; session-insert
      failure rolls back revocation; current-only logout leaves another session
      valid. Test an active-state change during password work and require rejection.
- [ ] Run new auth files and DB files with tsx under `--conditions=react-server`;
      observe the expected missing-module/export failures before implementation.
- [ ] Implement parser/actions with allowlisted safe state. Implement service:
      select by `lower(email)`, verify stored or dummy hash, reject inactive/mismatch,
      transactionally lock/recheck active user and unchanged password hash before
      revoking old token/creating session. Return unavailable for resource/DB failures.
- [ ] Implement digest-only revocation and register `tests/db/login.test.ts` in
      `test:db`. Use existing fixtures/proxy failure injection instead of test-only

- [ ] Run `pnpm test:auth` and `pnpm test:db`; require zero failures. Record checkpoint.
