# Domain documentation

## Before exploring a domain

Read the relevant entries in the root [glossary](../../GLOSSARY.md) and the
[architecture topic](../../ARCHITECTURE.md). Check the [decision index](../adr/README.md)
for ADRs affecting the area before proposing changes.

## Vocabulary and decisions

Use glossary terms in issues, designs, code, and tests. When a concept is missing,
first check whether an existing term already covers it. Record a resolved new
term in the root glossary; this repository uses one shared glossary.

Keep architectural decisions in `docs/adr/`, using the next available four-digit
number and a descriptive filename. Add new decisions to the index. If a proposal
contradicts an accepted ADR, identify the conflict explicitly and explain whether
the decision should be superseded; preserve the original rationale.
