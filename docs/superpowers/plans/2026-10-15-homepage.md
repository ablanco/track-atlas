# Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the starter page with the approved Track Atlas homepage in English and Spanish at `/en` and `/es`, with a maintainable light/dark theme system and without calls to action.

**Architecture:** Keep the existing Next.js App Router and render one shared homepage Server Component under `app/[locale]`. Use `next-intl` for translation catalogs, locale-aware navigation, and locale detection through `proxy.ts`. CSS custom properties define shared design tokens and semantic light/dark colors, mapped to Tailwind utilities. A small `next-themes` client boundary manages user preference; the homepage content stays server-rendered, including a themed static SVG map with no map service.

**Tech Stack:** Next.js 16.4.0, React 19.3.0, TypeScript, Tailwind CSS 4, `next-intl` and `next-themes` (compatible current releases, recorded in the lockfile), Node's built-in test runner, Playwright for theme browser tests.

**Spec:** `docs/DESIGN.md`, scoped by the approved visual mockup in `.superpowers/brainstorm/9577-1792052618/content/homepage-draft.html` and the user's instruction to add calls to action later.

## Global Constraints

- Keep documentation and code comments in English. All user-facing homepage text must be available in both English and Spanish, including navigation, accessible labels, notices, and metadata.
- Use `locales: ['en', 'es']`, `defaultLocale: 'en'`, and `localePrefix: 'always'`.
- `/en` and `/es` are the canonical language routes. Explicit prefixes take precedence over language preferences.
- Implementation defaults: `/` redirects using a remembered supported language preference, then the browser's `Accept-Language`, with English as fallback. A language switcher navigates between localized versions of the current page and remembers the selection using next-intl's locale cookie.
- Explain discovery, how the site works, signup benefits, and the open-source project.
- No signup, search, upload, or promotional action buttons; retain ordinary navigation and GitHub text links.
- Clearly distinguish planned features from currently working functionality.
- Do not implement authentication, track search, uploads, or a live map.
- Use `https://github.com/ablanco/track-atlas` for repository links.
- Add only `next-intl` and `next-themes` as runtime dependencies; `@playwright/test` is permitted as a development dependency. No git commits unless requested.
- Theme preference is `light`, `dark`, or `system`, defaults to `system`, and persists locally across reloads and locale changes. System preference changes apply live only while `system` is selected.
- Theme colors live exclusively in `styles/themes.css`, shared design scales in `styles/tokens.css`, and Tailwind mappings/base rules in `app/globals.css`. Components consume semantic utilities or variables, never raw palette colors or duplicated `dark:` color overrides.
- Light/dark theme is independent of language. Preserve the approved cream-and-green light design; use a coordinated dark palette, including the illustration, borders, focus rings, and native controls.

## Review Focus

- Narrow screens: no horizontal overflow at 375px.
- Keyboard use: navigation links have visible focus styling and a skip-to-content link.
- Assistive technology: one main landmark, one H1, ordered headings, and an accessible illustration label.
- Unbuilt features: no links to nonexistent routes or controls pretending to work.
- Search previews: replace starter title and description with Track Atlas metadata.
- Locale selection: test explicit prefix precedence, Spanish browser preference, English fallback, and remembered language preference.
- Translation parity: both catalogs must have matching keys and no empty strings; Spanish must not accidentally render English homepage content.
- Routing exclusions: static assets and Next.js internals must not be redirected to locale routes; unsupported locale paths must resolve to 404 rather than render an untranslated page.
- Theme startup: saved overrides apply before paint with no hydration warnings; server markup must not guess a local-storage preference.
- Theme interaction: keyboard-accessible translated controls expose Light/Dark/System, preserve selection after reload and locale changes, and follow live OS changes only in System mode.
- Theme readability: WCAG AA text contrast (4.5:1 normal text, 3:1 large text), visible focus and control boundaries, and legible illustration in both modes.
